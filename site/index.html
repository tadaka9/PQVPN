Ready01 / ROUTING

Weighted exit allocation

New sessions are assigned only to healthy, explicitly authorized exits according to capacity weight. Existing flows keep affinity, because shuffling TCP packets between countries is a creative way to reinvent packet loss.

  • Fail-closed without a healthy exit
  • Latency-aware deterministic tie-break
  • No per-packet striping or central telemetry
Ready02 / OBSERVABILITY

Flux fleet console

A local x86-64 terminal watches aggregate health over hardened SSH aliases. It sees load, memory and listeners—not peers, payloads or your browser history. The server may be suffering; it need not gossip.

  • Standalone Ubuntu/Debian package
  • No agent, account or analytics endpoint
  • Forwarding disabled; strict metric allowlist
Ready03 / SIDECARS

One-click transport engines

Install and manage udp2raw, V2Ray, Shadowsocks, DNSCrypt and obfs4 from a checksum-pinned catalog. A running helper proves only that a process is alive; unlike marketing, the UI does not confuse breathing with security.

  • Exact architecture matching
  • Isolated lifecycle and configuration
  • Explicit compatibility boundaries
Ready04 / INNER TUNNELS

WireGuard and OpenVPN

User-supplied WireGuard or OpenVPN configurations can run inside the managed path with the same model across GUI, CLI and TUI. Layers are visible, teardown is deliberate, and “double VPN” is not sold as double immortality.

  • Config-driven launch
  • Shared state across control surfaces
  • No silent route claims
Ready05 / DNS SHIELD

Privacy and threat presets

Reviewed Pi-hole profiles combine OISD and HaGeZi sources for balanced privacy, threat defence, family boundaries or an expert maximum. Aggregate blocked counts are useful; a dossier of everyone’s mistakes is not.

  • Named one-click profiles
  • Optional validated regex
  • No imported client or query history
Lab06 / ASGARD

Encrypted distributed storage

Asgard splits files into encrypted, content-addressed chunks and repairs replicas across independent devices. Signed consent expires; missing mounts fail closed. It still lacks network transport, so the yacht remains tragically unpurchased.

  • 4 MiB chunks and per-chunk keys
  • Independent-domain audit and verified repair
  • Local core only; network transport pending
Preview07 / MOBILE

Android and iOS shells

CI now produces an Android ARM64 preview and an unsigned iOS artifact for interface evaluation. The connect action remains disabled until Android VPNService and Apple Network Extension paths are implemented and verified.

  • Android ARM64 artifact
  • Unsigned iOS preview
  • No counterfeit “protected” indicator
Ready08 / STRANGENET

A world between real peers

Text, direct messages, voice, reactions and a native 2D social room live on established PQVPN sessions. Avatars move; participant IPs do not appear. The pixels have learned operational security before most corporations.

  • Authenticated E2E world presence
  • Replay and antiflood limits
  • Session-only positions and emotes

One clear path

From download to an authenticated path.

The desktop console guides the same four steps on every platform and reports only state produced by the canonical node.

  1. 01
    Install

    Choose a published test package and verify its checksum. Windows full-tunnel mode also requires the signed PQVPN NDIS driver.

  2. 02
    Validate

    Select a reviewed JSON configuration. The console asks pqvpn_node to parse and validate it before enabling Connect.

  3. 03
    Connect

    The node contacts a declared bootstrap endpoint and completes the hybrid handshake. “Mainnet connected” appears only after an authenticated peer session exists.

  4. 04
    Use

    Tunnel traffic, adaptive transport and StrangeNet share that session. Activity and diagnostics stay visible, and Disconnect rolls back the managed process.

Windows tunnel boundary

Driver state is checked, not assumed.

The console distinguishes ready, missing and access-denied states. UDP-only mode remains an explicit connectivity test and never claims that system traffic is tunneled.

Dual-stack without theatre

IPv4 and IPv6 are measured separately.
