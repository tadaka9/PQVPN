One clear path

From download to an authenticated path.

The desktop console guides the same four steps on every platform and reports only state produced by the canonical node.

  1. 01
    Install

    Choose a published test package and verify its checksum. Windows full-tunnel mode also requires the signed PQVPN NDIS driver.

  2. 02
    Validate

    Select a reviewed JSON configuration. The console asks pqvpn_node to parse and validate it before enabling Connect.

  3. 03
    Connect

    The node contacts a declared bootstrap endpoint and completes the hybrid handshake. “Mainnet connected” appears only after an authenticated peer session exists.

  4. 04
    Use

    Tunnel traffic, adaptive transport and StrangeNet share that session. Activity and diagnostics stay visible, and Disconnect rolls back the managed process.

Windows tunnel boundary

Driver state is checked, not assumed.

The console distinguishes ready, missing and access-denied states. UDP-only mode remains an explicit connectivity test and never claims that system traffic is tunneled.

Hardened operations

Small attack surface. Automatic recovery.

The dedicated bootstrap and mainnet exit run without login privileges, expose PQVPN only over UDP/9090, bound pre-authentication work, and install checksum-verified releases through atomic updaters with rollback.

A room between authenticated peers

Enter StrangeNet.

Established PQVPN peers can share a bounded conversation room without a central chat service. Text, emoji, stickers, reactions and delivery receipts use a session-separated E2E key and authenticated sender identity.

Local-first

No public history, account database or analytics endpoint.

Bounded frames

2 KiB messages, strict UTF-8 parsing and bounded replay state keep conversation traffic predictable.
