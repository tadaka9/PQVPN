# PQVPN 0.0.15 beta security audit

Scope: StrangeNet group delivery, public-identity claims, desktop integration,
and the existing release gates. This is an internal engineering audit, not an
independent cryptographic assessment.

## Findings closed for this beta

- **Implicit room audience:** a room previously meant universal fan-out or one
  peer. Explicit groups now contain the local identity plus 2–63 distinct,
  canonical 32-byte peer identities.
- **Silent group shrinkage:** group delivery now checks every authenticated
  session before the first send and returns failure if any member is offline.
- **Recipient substitution:** group identities remain pinned for the joined
  room. Neither the node nor GUI falls back to universal fan-out.
- **Central verification pressure:** public badges are detached, expiring
  Ed25519 + ML-DSA claims. A claim is meaningful only when its issuer key is in
  the user's local trust store; badges do not alter encryption or authorization.
- **GUI state ambiguity:** the peer list uses explicit multi-selection, freezes
  during a joined room, reports participant count, and disables sending when a
  selected member disconnects.

## Security properties retained

- Message bodies remain protected by the per-recipient StrangeNet application
  key derived from an authenticated PQVPN session.
- Sender/session binding, AEAD associated data, replay windows, message size
  limits, anti-flood buckets, bounded recipients, and memory-only history are
  unchanged.
- Verification claims contain no private identity documents and introduce no
  recovery key, moderation key, server-side escrow, or decryption backdoor.

## Open limitations

- This beta is live-session P2P. It does not provide asynchronous offline
  delivery, durable history, MLS-style membership epochs, or global discovery.
- The preflight for all group members is fail-closed, but UDP cannot provide an
  atomic all-recipient commit. Delivery receipts remain the source of truth.
- Trust-store distribution and revocation are local policy. A famous name or
  party label is not trustworthy unless the user independently trusts the
  signing issuer and evidence URI.
- The Qt monitor remains a large translation unit. The group change is kept
  small and state-driven, but further extraction into testable presenters is
  recommended before expanding the UI again.
- Independent protocol review, fuzzing, and three-device WAN interoperability
  testing remain required before calling the feature production-ready.

## Release acceptance checks

- Three-participant membership accepts two distinct remote identities and
  rejects smaller, duplicate, malformed, oversized, or self-containing sets.
- Tampered, expired, future-dated, or untrusted public claims fail verification.
- Existing release Python tests, C++ tests, GUI smoke/render/scroll checks,
  CodeQL, hardening, native builds, package lifecycle, and attribution gates
  must all pass for the exact release commit.
